# NOVA 1.0 — единое офлайн-приложение (решение по архитектуре)

**Статус:** принято направление, нативная генерация изображений **ещё не реализована и не подтверждена** на Redmi. Этот документ — спецификация для следующего проверяемого прототипа; он не даёт права выпускать тестовую APK с фиктивной генерацией.

## Пользовательский результат

Единственное установленное приложение **NOVA**. Запрос «Нова, создай страшный кадр с зеркалом» выполняется так:

```text
Голос или чат
    ↓
NOVA Orchestrator (детектор намерения + локальный план)
    ↓
Разрешения / каталог доступных моделей / ресурсы устройства
    ↓
NOVA Director (Gemma) → Inner Voice → Critic
    ↓
ImageEngine (собственная native .so внутри NOVA)
    ↓
PNG в галерее и проекте NOVA
    ↓
Vision / Critic (после внедрения зрительного анализа)
    ↓
FFmpeg / монтаж → MP4 (следующий этап)
```

Ни одно штатное действие не требует перехода в другое приложение. Выбор моделей из UI — дополнительная настройка, **не обязательный шаг на каждый запрос**.

## Исходное состояние

- Текстовый GGUF-движок уже интегрирован через `nova-llama` + JNI + Kotlin.
- Совет / внутренний голос / Critic должны оставаться работоспособными при переключениях моделей.
- В экспериментальных ветках реализован путь к **внешнему** Local Dream через localhost 8081/8808. **Это временный адаптер, не целевая архитектура**.
- Пользователь проверил Local Dream с Absolute Reality: CPU 512×512 — 5:16; GPU 512×512 — 15:44. Эти числа **не распространяются** на другую native-библиотеку. Реалистичные лица не удовлетворили пользователя.
- Модели, хранящиеся в приватном каталоге стороннего приложения, NOVA не может напрямую читать из-за Android sandbox. Нужен собственный совместимый набор весов, импортированный с согласия пользователя.

## Выбор технологии (после чтения upstream 2026-11-05)

### Первый кандидат: stable-diffusion.cpp (MIT)

- Самостоятельная C/C++ библиотека с публичным C API.
- Веса: SD 1.x/SDXL и другие; `.safetensors` / `.gguf` при поддерживаемой архитектуре.
- Android: документирована сборка NDK для OpenCL/Adreno; CPU — обязательный fallback.
- В нашем проекте будет **отдельный модуль и отдельная native-библиотека** (`libnova-image.so`), а не прямое совместное линкование с `libai-chat.so`. Причина: обе системы используют собственные версии GGML; возможны конфликты символов/ABI.
- **Не считать совместимыми** текстовые GGUF и диффузионные GGUF. Нужна проверка класса модели и файловых компонентов.

### Резерв: MNN Diffusion (Apache 2.0)

- Android/CPU/OpenCL; есть нативное семейство diffusion.
- Для SD 1.5 нужны подготовленные `.mnn` ресурсы (text_encoder, unet, vae_decoder, tokenizer).
- Нельзя просто передать уже загруженный `.safetensors` или вес из Local Dream без преобразования.
- Использовать, если первый кандидат не проходит реальные ограничения по скорости/памяти/поддержке.

**Лицензии моделей проверять отдельно:** MIT/Apache лицензия движка не переносится на веса.

## Модули NOVA

```text
android/app
  ├── NovaBrain / Dialogue        (существующий GGUF inference)
  ├── NovaDirector                (совет, Inner Voice, Critic)
  ├── NovaOrchestrator            (маршрутизация структурированных задач)
  ├── NovaModelRegistry           (каталог, форматы, контрольные суммы, выбор)
  ├── NovaImagePlugin             (будущий JNI facade, без обязательного localhost)
  ├── NovaMediaEngine             (позже FFmpeg)
  └── NovaGallery / projects      (контент и история результатов)
android/nova-llama               (не изменять без необходимости)
android/nova-image               (новый Native CMake + JNI, отдельная .so)
```

Предлагаемый контракт `ImageEngine`:
- `isAvailable(): bool` — есть ли native библиотека и совместимая модель;
- `validateModel(path): ModelInfo` — формат, архитектура, лицензия/метаданные, память;
- `loadModel(path, backend: cpu|gpu): LoadResult` — строго один runtime;
- `generate(prompt, negative, size, steps, seed, onProgress): ImageResult`;
- `cancel()` — кооперативная отмена, без убийства всего приложения;
- `unload()` — гарантированное освобождение native ресурсов.

**Не объявлять capabilities=true, пока тест не подтвердил функцию.** Заглушки должны отвечать `not_installed` / `not_ready`, не «успешно».

## Менеджер моделей: автоматизация без потери контроля

1. Обнаружить собственные модели NOVA; проверить формат, размер, совместимость движка, hash.
2. По намерению выбрать категорию: conversation / image_generation / vision / speech / video_tool.
3. Если уже есть совместимый движок и веса — использовать без лишних вопросов.
4. Если нет, предложить *конкретный* проверенный ресурс, его размер, источник, лицензию; загрузить с подтверждения.
5. DownloadManager → staging → SHA256 → validateModel → atomically activate.
6. Модели не держать все одновременно в RAM. При тяжёлой диффузии останавливать ответ LLM и выгружать при необходимости (после завершения текста), затем восстанавливать Gemma.
7. Ошибка/нехватка памяти/перегрев: остановка, освобождение памяти, объяснение, безопасный retry только после явного действия.
8. Удаление старых моделей — только с подтверждением после проверки, что они не активны, есть копия и их не используют проекты.

Разрешения: Интернет нужен только для явно разрешённой загрузки; без полного доступа к файловой системе, без root, без shell. Сохранение через MediaStore и Android System Picker.

## Последовательность разработки и критерии готовности

### Gate 1 — нативная сборка, отдельная экспериментальная ветка
- Зафиксировать конкретный upstream commit и лицензии сторонних компонентов.
- Android arm64-v8a; CMake/NDK; линковать отдельную `.so`, не изменяя `nova-llama`.
- JNI smoke test: load/unload библиотеки, возврат capability и ошибки, heap-safe cancellation.
- GitHub CI: unit/interop tests + assembleDebug + подтверждение, что нужная `.so` присутствует в APK.
- **Не выпускать пользователю APK без рабочей команды генерации**.

### Gate 2 — реальный результат на Redmi
- Импортировать одну разрешённую SD 1.5 модель в NOVA (нельзя повторно использовать приватное хранилище Local Dream).
- Авиарежим, 256×256 CPU → реальный PNG, затем 512×512 при приемлемой памяти.
- Замерить время, пиковую RAM, перегрев, размер PNG, частоту сбоев.
- Проверить: Gemma чат → ImageEngine → unload → Gemma чат, отдельно Director Council и Critic.
- Пробовать GPU только после стабильного CPU; измерять, а не обещать ускорение.

### Gate 3 — одна команда вместо экранов настройки
- «Нова, нарисуй…» → структурированная задача → авто-выбор модели → генерация → сохранить PNG → реальный статус.
- Ошибки доступны из чата, пользователь не ищет файлы/серверы.
- Удалить обязательную зависимость от Local Dream, но сохранить старые экспериментальные ветки как резервные/исторические.
- После подтверждения: встроенный Vision и качество; позже FFmpeg / голос / видео.

## Запреты до Gate 2

- Не удалять и не переносить `nova_dual_mind.py`, `nova_critic.py` и GGUF без инвентаризации зависимостей и тестов.
- Не подменять изображение текстовой отговоркой или фиктивным PNG.
- Не переключаться назад на обязательное внешнее приложение.
- Не объявлять «полностью автономной» функцию, требующую ручного запуска Local Dream.
- Не заменять установленную рабочую NOVA неподтверждённой APK.
